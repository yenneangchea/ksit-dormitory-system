Runtime behavior

Drive-primary with a safe fallback boundary

The adapter does not make a best-effort guess. Its storage path is deterministic from the two required server-side configuration values.

A

Both Drive values configured

Service-account JSON and the root folder ID are present in the backend environment.

Runtime outcomeCreates or reuses the student folder, uploads artifacts to Google Drive, and records Drive references in Supabase.
B

No Drive values configured

Neither Drive variable is present, such as during the current fallback-ready deployment.

Runtime outcomeUses the existing private Supabase buckets and preserves the same lifecycle state transitions and access controls.
C

Only one value configured

A root folder without credentials, or credentials without a root folder, creates an unsafe ambiguous state.

Runtime outcomeStops with an explicit configuration error. It never silently writes sensitive files to an unintended store.
Activation rule: set both variables in the backend Vercel project, then redeploy.Fallback remains private by design.
